# Production Readiness Report — demo-mechanik

**Project:** demo-mechanik (Angular 19 + TypeScript + Signals + Tailwind, static portfolio demo)
**Audit Date:** 2026-07-22
**Auditor:** Production Readiness Auditor Agent
**Scope:** Focused review per `plans/2026-07-22-production-readiness.md` — SEO, Core Web Vitals/performance, PWA correctness, accessibility, runtime console errors, SPA routing on GitHub Pages, `npm audit`, secrets, build/CI. Explicitly out of scope: real backend, GDPR/cookie consent, payments.

**Method:** Static source review, a clean `ng build` (production config), inspection of the actual `dist/demo-mechanik/browser` output, `npm audit --json`, and live testing against the deployed site (`https://konradxmalinowski.github.io/demo-mechanik/`) via a real browser (console messages, network, keyboard-focus walkthrough, deep-link navigation).

---

## Executive Summary

The build is clean (no errors/warnings, budgets respected, 6 routes prerendered, route- and component-level code splitting working) and there are no committed secrets. However, live testing surfaced a real, reproducible SPA-routing bug (GitHub Pages `404.html` redirect has no matching decoder in `index.html`, confirmed in production — an unknown URL silently loads the homepage with a garbled query string instead of a real 404 or a restored route), a brand/content inconsistency between the static `index.html` meta tags and the runtime `SeoService` (two different business names/cities render depending on whether a crawler reads static HTML or executes JS), a broken/absolute `og:image` on every route, an identical canonical URL on all 6 pages (should be per-page), a keyboard-focus-visibility gap on 4 booking form fields (confirmed by live tab-through test), a render-blocking Google Fonts `@import`, and 40 `npm audit` findings including one that is **not** a devDependency-only issue: `@angular/core@19.2.25` (the exact installed version) is affected by a high-severity client-hydration DOM-clobbering advisory. None of this touches the explicitly out-of-scope areas (backend, GDPR, payments). Recommended immediate actions: fix the canonical/og:image/brand-consistency cluster (cheap, high SEO impact), add a visible focus style to the 4 unstyled form fields, and either patch or accept-and-document the Angular hydration CVE.

### Critical Blockers (must fix before treating this as a polished portfolio piece)

None are "critical" in the security/data-loss sense used for real production apps (there is no backend, no user data). Treating "blocker" here as "an actual visitor or recruiter will notice something broken":

1. Deep-link/404 handling is broken in production (confirmed live) — visiting any unknown or mistyped URL under `/demo-mechanik/` silently loads the homepage with a garbled `?%2F...` query string visible in the address bar.
2. Canonical URL is identical on all 6 pages — every subpage claims the homepage as canonical, which is a genuine SEO defect a technical reviewer would spot immediately.
3. `og:image` is broken on every route (points to a file that doesn't exist, `/assets/og-mechanik.jpg`, with a leading slash that would resolve outside the GitHub Pages subpath even if it existed) — link previews (Slack, LinkedIn, WhatsApp) will show no image.
